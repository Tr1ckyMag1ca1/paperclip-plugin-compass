<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Plugin ↔ Paperclip Host | Plugin SDK bridge; host validates all DB access via capability model |
| Plugin SDK ↔ Paperclip Postgres | Plugin SDK enforces auth; plugin never calls Postgres directly |

## STRIDE Threat Register

Phase 1 is read-only (no writes) and has no network I/O, so STRIDE threats are minimal. Schema validation (D-08) and input validation (MODE-04 in Plan 2) are the only attack surfaces.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-V1 | Input Validation | MODE-04 chat classifier (Plan 2) | mitigate | Lightweight regex only; no SQL, no command injection surface (founder-controlled input) |
| T-01-V2 | Access Control | Plugin SDK calls via XC-01 adapter | accept | Plugin SDK enforces host auth; adapter routes all calls through SDK (no direct Postgres) |
| T-01-V3 | Error Handling | Schema validation on startup | mitigate | Founder-readable error messages only; never expose stack traces (D-08) |

**Assessment:** No ASVS Level 1 violations in Phase 1. Read-only operation eliminates authentication, session, and access control STRIDE categories. Input validation limited to founder-controlled chat. Error handling standardized.
</threat_model>
