## Typography

Inherited from Paperclip host (Plugin SDK provides design tokens):

| Role | Size | Weight | Line Height | Class Usage |
|------|------|--------|-------------|-------------|
| Body (paragraph) | 14px | 400 (normal) | 1.5 (24px) | `text-body` |
| Label (form labels, captions) | 12px | 500 (medium) | 1.4 (17px) | `text-label` |
| Heading (section headers, h3/h4) | 18px | 600 (semibold) | 1.3 (23px) | `text-heading` |
| Display (interview section title, h2) | 24px | 700 (bold) | 1.2 (29px) | `text-display` |

**Rationale:**
- Body 14px × 1.5 — readable in narrow sidebar, follows Paperclip conventions
- Label 12px — form field descriptors, inline hints (matches Paperclip form pattern)
- Heading 18px — visual break between form sections, question groups
- Display 24px — interview section title (e.g., "Big Picture"), command attention

**Application in Phase 2:**
- Interview section title: `text-display font-bold` — "Big Picture", "Revenue & Customers", etc.
- Question prompt: `text-body font-normal` — interview questions, instructions
- Form labels: `text-label font-medium` — input labels, hint text
- VISION preview heading: `text-heading font-semibold` — section names in rendered VISION.md

## Color

Inherited from Paperclip host (using host design token class names):

| Role | Class | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-background` / `text-background` | Form backgrounds, interview panel background |
| Secondary (30%) | `bg-card` / `border-border` | Section dividers, collapsible headers, form field backgrounds |
| Accent (10%) | `text-accent` / `border-accent` / `ring-accent` | Mode-specific icons (compass icon in banner), required-field indicators, focus rings |
| Destructive | `text-destructive` | "Discard draft" button only (red, not used elsewhere) |
| Foreground | `text-foreground` | Primary text (body copy) |
| Foreground muted | `text-foreground/70` | Secondary text (hints, descriptions, metadata) |

**Accent reserved for:**
1. Mode icon in ModeBanner (compass rose)
2. "Required field" visual indicators (e.g., red asterisk on interview questions)
3. Focus ring on interactive form elements (e.g., button focus, select focus)
4. Confirm modal "I confirm" CTA button background/border

**Usage constraint:** Accent is NOT used for general interactive elements (links, toggles). Those use `text-foreground` with underline or `bg-card` with border.

| Confirm modal body | "Apply will write the vision document, create [N] agents, file [N] kickoff issues, and start the company heartbeating. This is reversible only by manual cleanup. [List write counts]" | Transparent, actionable, acknowledges irreversibility |
| Confirm modal primary button | "I confirm — apply changes" | Explicit founder consent, past-tense action confirmation |
| Confirm modal secondary button | "Cancel" | Simple, no icon needed |
| Apply progress step labels | "Validating… ✓ Preflight", "Writing… ✓ Vision doc", "Provisioning… ✓ Agents", "Creating… ✓ Kickoff issues", "Queuing… ✓ Wakeups" | Sequential, status-driven, checkmarks on completion |
| Error state (preflight) | "Can't start: {specific reason}. {Next step to fix.}" e.g., "Can't start: Company already has a VISION.md. To rewrite it, run a Reposition interview instead." | Problem-first, solution-oriented, non-technical |
| Error state (mid-Apply rollback) | "Apply failed at [step]. {N} items have been cleaned up. Check [link to company] before retrying." | Transparency + recovery path |
| Empty interview state | "No draft in progress." + "Start the interview" button | Clear, actionable CTA |
| Resume button (mid-interview on return) | "Resume: [Section name], Question [N]" | Shows exactly where founder left off |
| Discard draft confirmation | "Are you sure? Your draft interview progress will be lost." + "Discard" / "Cancel" | Irreversible action, confirm intent |

## Interaction Patterns

### Interview Flow (Main Panel)

**Linear progression with full back-nav:**

1. **Section Navigation Rail** (left edge or top tabs — TBD by planner)
   - Shows all 6 section names: "Big Picture", "Revenue & Customers", "Growth & Marketing", "Product Direction", "CEO Autonomy", "Vision & Identity"
   - Current section highlighted (accent color or bold font weight)
   - Clickable to jump to any prior section
   - Cannot jump forward (Next button disabled until current questions answered)
   - Shows progress indicator (e.g., "3 of 6 sections complete")

2. **Question Renderer** (form area)
   - One question per viewport (or question group if related, TBD by planner)
   - Question prompt in `text-body` font
   - Question type determines input:
     - `free-text-short` → single-line text input
     - `free-text-long` → textarea (minimum 4 rows, expand on input)
     - `single-choice` → radio buttons (vertically stacked) OR select dropdown (if 8+ options; planner decides)
     - `multi-choice` → checkboxes (vertically stacked)
     - `conditional-follow-up` → appears only if parent question answered with triggering value
   - Hint text below input in `text-foreground/70` color
   - Required-field indicator if question is required (red asterisk OR `(Required)` label)
   - Optional-field indicator if not required (`(Optional)` in gray)
   - Answer persists to Plugin SDK worker-state automatically on field blur or keystroke throttled

3. **Navigation Buttons** (below questions)
   - "← Back" button (left) — disabled on first section, else navigates to prior section preserving all answers
   - "Next: [Section name]" button (right) — disabled until all required questions answered, on click saves state and advances to next section
   - On final section: "Review & Apply" button instead of "Next"

4. **Preset Selection** (TBD placement — planner decides start vs mid-interview vs end)
   - Single-choice radio buttons showing preset options (inherited from company-wizard)
   - Locked once selected (no change during interview — prevents re-render of branching questions)
   - Selected preset shown in preview/confirm modal

### Preview Screen (Linear-scrollable modal or side panel)

**Header:** "Here's the company you're founding. Edit anything before you apply."

**Content (scrollable):**
1. Rendered VISION.md (read-only by default)
   - Markdown formatted (headers, paragraphs, lists)
   - Section structure matches `src/content/vision-template.md`
   - All required slots populated (mission, mandate, voice, principles, success_criteria) — no placeholders
   - Derived slots computed (e.g., "12-mo goal" from revenue + customer count)

2. **Edit Toggle** (above VISION.md)
   - "Edit" button → toggles on, renders textarea with VISION.md markdown source
   - "Done editing" button → toggles off, re-renders from edited markdown (basic validation: no empty required slots)
   - Inline markdown editing (not CodeMirror — plain textarea for v1 per D-deferred)
   - Founder edits for voice/polish only — structure/sections not validated

3. **Provisioning Summary** (below VISION.md)
   - Preset name (e.g., "Launch MVP")
   - Agents to create: list names, roles (e.g., "Alice — CEO, Bob — Engineer, Carol — Designer")
   - Kickoff issues to file: count + brief list (e.g., "5 issues: [list titles]")
   - Write counts visible (used in final confirm modal)

**Action buttons:**
- "Back to interview" (left) — returns to interview, preserves answers + edited VISION
- "Confirm & apply" (right) → opens final confirmation modal

### Confirmation Modal (Final Gate)

**Modal header:** "Apply changes to Paperclip"

**Body:**
```
Apply will:
- Write the company vision document
- Create 5 agents (CEO, Product, Growth, Engineer, Admin)
- File 5 kickoff issues
- Queue wakeups to start the company heartbeating

This is reversible only by manual cleanup in Paperclip.

Write count: 1 document, 5 agents, 5 issues, 5 wakeups
```

**Buttons:**
- "Cancel" (secondary) — returns to preview screen
- "I confirm — apply changes" (primary) → runs Apply step

### Apply Progress UI (Modal or full-panel overlay)

**During Apply (blocking interaction):**

Sequential step indicator:
```
Validating setup…
✓ Preflight checks
Writing vision document…
✓ Vision doc saved
Provisioning agents…
✓ 5 agents created
Creating kickoff issues…
✓ 5 issues filed
Queuing company heartbeat…
✓ Wakeups queued
```

Each step shows:
- Status: "…" (in-progress) or "✓" (complete)
- Step name

**On success:**
```
✓ Company founded!

Your new company "Acme" is now heartbeating. Check the inbox for kickoff issues.

[Go to company] button → closes plugin panel, navigates to company in Paperclip UI
```

**On failure at any step:**
```
Apply failed: {Step name}

Error: {Readable error message}
Next step: {Recovery instruction}

Rollback:
✓ Kickoff issues deleted
✓ Agents deleted  
✓ Vision document deleted

Retry: [Retry button] | [Close] button
```

## Component Inventory (Phase 2 New Components)

| Component | Purpose | Behavior |
|-----------|---------|----------|
| `InterviewSection` | Renders single interview section with question list | Manages local question state, validates required fields, auto-persists to worker-state |
| `QuestionRenderer` | Renders individual question based on `type` field | Handles all 5 question types, conditional show-if logic, focus management |
| `SectionNavRail` | Left-edge or top navigation showing all 6 sections | Shows progress, clickable jump-to (prior only), highlights current |
| `PresetSelector` | Radio button group for choosing found preset | Locked once selected, not shown in interview — appears only at start or explicit modal |
| `VisionPreview` | Read-only or editable markdown display of generated VISION.md | Toggle "Edit" → textarea, validation on toggle-off |
| `ProvisioningSummary` | Lists agents, issues, write counts | Used in both preview + confirm modal |
| `ConfirmationModal` | Final gate: "I confirm — apply changes" | Two-stage approval gate per FOUND-11 |
| `ApplyProgress` | Sequential step indicator with status | Shows preflight → doc → agents → issues → wakeups |
| `ApplyErrorDisplay` | Error message with recovery steps | Readable problem + solution, rollback status |
| `InterviewDraftState` | Saves/restores interview progress in Plugin SDK worker-state | Invisible to founder, persists on blur/keystroke |

## Form Validation Rules

| Field Type | Validation | Error Message |
|-----------|-----------|---------------|
| `free-text-short` | non-empty, max 200 chars | "Required — max 200 characters" |
| `free-text-long` | non-empty, max 2000 chars | "Required — max 2000 characters" |
| `single-choice` | exactly one selected | "Choose one option" |
| `multi-choice` | at least one selected (if required) | "Select at least one" |

**Required slot check (before Apply):**
- `mission` — non-empty, >20 chars
- `mandate` (CEO mandate) — non-empty, >20 chars
- `voice` — non-empty, >50 chars
- `principles` — non-empty list of ≥3 items
- `success_criteria` — non-empty, ≥2 criteria

On validation fail: block Apply, show error banner with specific slot names + "Edit vision section X" link.

## Responsive Constraints

**Sidebar fixed width:** ~360px (Paperclip host standard)

**Layout approach:**
- Main panel scrollable vertical (no horizontal scrolling)
- Interview questions: `max-width: 100%` of panel width
- Modals and overlays: centered, `max-width: 90vw` (respect sidebar constraint)
- Form fields: full-width within panel padding

**No mobile optimization in v1** — plugin runs desktop-only in Paperclip UI.

---

## Accessibility

- All interactive elements keyboard-navigable (Tab, Enter, Space)
- Form labels linked to inputs via `htmlFor` / `id`
- Required fields marked with `aria-required="true"`
- Error messages linked to inputs via `aria-describedby`
- Modal backdrop blocks background interaction (focus trap)
- Skip navigation not needed (narrow sidebar scope)

## Designer Notes (Claude's Discretion)

This contract locks the **what** (behavior + copy + visual relationships) but leaves **where** for the planner:

1. **Section nav rail placement** — top tabs, left sidebar rail, or stepping indicator? Recommend left-rail for consistency with Paperclip sidebar, but step indicator acceptable if space tight.
2. **Preset selection timing** — start of interview (can branch questions), mid-interview (no branching), or end (locked late)? Recommend start to enable conditional questions, but planner decides based on UX flow testing.
3. **Preview panel layout** — modal overlay, full-panel slide-in, or side panel? Modal recommended (simpler state management), but side panel acceptable if mobile-like responsive not required.
4. **Question rendering density** — one question per scroll, or three related questions in a group? Recommend one per scroll (reduces cognitive load), but planner may optimize for interview duration.

All above locked in **planner** phase, not here. UI-SPEC provides the contract; planner places components on the grid.
