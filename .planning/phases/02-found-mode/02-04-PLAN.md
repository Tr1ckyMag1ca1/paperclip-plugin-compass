### FoundPanel State Machine

From D-13, UI-SPEC lines 137–150, PATTERNS.md lines 628–702:

```
interview
  ↓ (all required questions answered + preset selected)
preview
  ↓ (click "Confirm & apply" after optional edit)
confirming
  ↓ (ConfirmationModal shows, founder clicks "I confirm")
applying
  ↓ (ApplyProgress shows)
complete  (success)
  ↓ (founder can close or "Go to company")
[exit]

error
  ↓ (failure at any step)
  ↓ (ApplyErrorDisplay shows with retry button)
[back to preview / close]
```

Four persistent states: interview, preview, confirming, applying (+ transient: complete, error).

Transitions enforce two-stage gate: cannot skip preview → confirm.

### Worker Handlers Needed

These handlers wire the UI hooks (useInterviewDraft, usePluginAction) to the actual backend logic (apply.ts, worker-state APIs).

**`src/ui/found/FoundPanel.tsx` — Orchestrator**

Export:
- `export function FoundPanel(): React.ReactElement`

Props (from parent MainPanel):
- Implicit: companyId (via Plugin SDK context)

State:
- `currentSection: number` (0–5)
- `answers: InterviewAnswers` (all answers keyed by question ID)
- `selectedPreset: PresetDefinition | null` (locked once selected)
- `step: "interview" | "preview" | "confirming" | "applying" | "complete" | "error"`
- `vision: FilledVision | null` (rendered VISION.md)
- `applyResult: ApplyResult | null` (on success or error)

Logic (from PATTERNS.md lines 633–702):

1. **On mount:**
   - Load interview sections via markdown loader
   - Call useInterviewDraft(companyId) to load draft
   - Set answers from draft (resume mid-interview if applicable)

2. **Interview step:**
   - Render SectionNavRail (progress, back-nav)
   - Render InterviewSection for current section
   - On "Next": validate required answers, advance section (or jump to preview if last section)
   - On "Back": go to prior section
   - Auto-save answers via saveDraft() on each change
   - Show PresetSelector (placement: at start per D-14 + D-01; locked after selection)

3. **Preview step:**
   - Fill VISION template via fillVisionTemplate(answers)
   - Quality check via checkVisionQuality(vision)
   - Render VisionPreview with edit toggle
   - Show ProvisioningSummary
   - On "Back to interview": return to interview, preserve answers
   - On "Confirm & apply": validate quality checks, jump to confirming step

4. **Confirming step:**
   - Render ConfirmationModal
   - On "I confirm": set step to "applying", call Apply action
   - On "Cancel": return to preview

5. **Applying step:**
   - Call usePluginAction("runApply") with vision, preset, companyId
   - Render ApplyProgress showing current step
   - On success:
     - Render success message
     - Button: "Go to company" (closes panel, navigates to company in Paperclip)
     - Automatically clear draft (clearDraft())
   - On error:
     - Render ApplyErrorDisplay with rollback status
     - Buttons: "Retry" (re-enter applying), "Back to preview" (return to preview)

All state flows are explicit in code. No accidental skips of approval gates. Type safety via discriminated union on `step`.

1. **Handler: `loadInterviewDraft`**
   ```typescript
   export const handlers = {
     // ... existing handlers from Phase 1 ...
     
     loadInterviewDraft: async (ctx: PluginContext, { companyId }: { companyId: string }) => {
       // Load draft from worker-state
       const draft = await ctx.state.get({
         scopeKind: "company" as const,
         scopeId: companyId,
         namespace: "compass:found:draft",
         stateKey: "current",
       });
       return draft || null;
     },
   };
   ```

2. **Handler: `saveInterviewDraft`**
   ```typescript
   export const handlers = {
     saveInterviewDraft: async (
       ctx: PluginContext,
       { companyId, answers }: { companyId: string; answers: InterviewAnswers }
     ) => {
       // Save draft to worker-state
       await ctx.state.set(
         {
           scopeKind: "company" as const,
           scopeId: companyId,
           namespace: "compass:found:draft",
           stateKey: "current",
         },
         answers
       );
     },
   };
   ```

3. **Handler: `runApply`**
   ```typescript
   export const handlers = {
     runApply: async (
       ctx: PluginContext,
       {
         companyId,
         vision,
         preset,
       }: { companyId: string; vision: FilledVision; preset: PresetDefinition }
     ) => {
       // Call Apply orchestrator
       const result = await applyFound(ctx, companyId, vision, preset, generateApplyRunId());
       
       // If successful, clear draft
       if (result.success) {
         await ctx.state.set(
           {
             scopeKind: "company" as const,
             scopeId: companyId,
             namespace: "compass:found:draft",
             stateKey: "current",
           },
           null
         );
       }
       
       return result;
     },
   };
   ```

All handlers:
- Take PluginContext (from Plugin SDK worker context)
- Take typed args
- Are async (SDK calls are async)
- Return typed results
- Are automatically exposed via Plugin SDK handler registration

**Integration notes:**
- FoundPanel calls usePluginAction("runApply") which wires to worker.ts handler
- useInterviewDraft hook calls usePluginData("loadInterviewDraft") and usePluginAction("saveInterviewDraft")
- All state management is coordinated through hooks + callbacks

All components are linked. State flows through FoundPanel. No orphaned components.
