<threat_model>

## Trust Boundaries

| Boundary | Description | Risk |
|----------|-------------|------|
| Founder input → shift classifier | Free-form founder intent describing strategic shift | Low — classification is deterministic heuristics only; confidence scores flag low-confidence shifts; no LLM decision authority |
| Shift scope → interview filter | Founder-modified section list from UI | Low — filter is deterministic list subset operation; cannot cause unintended actions |
| VISION.md parser → seed-answers | Existing VISION content used to pre-fill interview | Medium — if VISION.md malformed, seed-answers may return partial/empty answers; founder sees empty fields and must fill manually (safe fallback) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Elevation of Privilege | classifyShift keyword matching | mitigate | Deterministic keywords only (no wildcard matching, no regex backtracking); confidence score flags low-confidence shifts; list of allowed keywords documented inline for audit |
| T-05-02 | Tampering | getSection­AnswerSeed VISION extraction | mitigate | Pure function reads from validated ParsedVision (output of parseVision from Phase 3); no direct file reads; no unsafe markdown processing |
| T-05-03 | Denial of Service | filterInterviewToScope array iteration | mitigate | Array size bounded by 6 interview sections (hard limit); O(n) iteration where n=6; no recursive calls; no unbounded loops |
| T-05-04 | Spoofing | idempotency key format | accept | Format is non-cryptographic (digest, not signature); used only for deduplication, not authentication; attackers cannot forge valid keys (would need to know companyId + runId) |

</threat_model>
