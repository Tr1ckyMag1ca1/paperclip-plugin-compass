Create src/ui/reposition/RepositionPanel.tsx as main entry point with state machine orchestration (per D-13, 05-UI-SPEC):

State machine with 9 states:
- empty: no reposition in progress
- intent: founder enters shift description
- scope-confirm: founder confirms/edits affected sections
- interview: scoped re-interview with pre-filled answers
- preview: per-section amendment preview
- cascade-review: per-agent decision interface
- confirming: final confirmation modal
- applying: progress bar during apply
- complete: success screen
- waiting-approval: founder+ceo approval gate (CEO reviewing)
- error: error display with retry

**Component structure:**

1. **useRepositionRunState hook:** Load cached run state from worker-state on mount
   - If cached run exists and intent populated: resume at scope-confirm
   - Otherwise: start at empty

2. **State management:**
   - step: RepositionStep (tracks current state)
   - intent: string (shift description)
   - shiftScope: ShiftScope (classified sections)
   - userScope: VisionSectionId[] (after founder override)
   - interviewAnswers: InterviewAnswers (from scoped interview)
   - amendments: Amendment[] (generated before preview)
   - cascadePlan: CascadePlan (from cascade planning)
   - applyError: string | null
   - routingConfig: approval routing from inventory

3. **Handlers (step progressors):**
   - handleIntentSubmit(intent) → classify shift → set scope → advance to scope-confirm
   - handleScopeConfirm(userScope) → save to state → advance to interview
   - handleInterviewComplete(answers) → save answers → generate amendments → advance to preview
   - handlePreviewContinue() → advance to cascade-review
   - handleCascadeConfirm(cascadePlan) → advance to confirming
   - handleApply() → call applyRepositionAmendments → advance to applying
   - handleApplyProgress(status) → update progress
   - handleApplyComplete() → advance to complete
   - handleApplyError(error) → set applyError → advance to error
   - handleDiscard() → clear run state → advance to empty

4. **Render logic:**
   - If step === "empty": <EmptyRepositionState onStart={...} />
   - If step === "intent": <IntentEntry onContinue={handleIntentSubmit} />
   - If step === "scope-confirm": <ScopeConfirmation classifiedScope={shiftScope} onConfirm={handleScopeConfirm} onBack={...} />
   - If step === "interview": <RepositionInterviewFlow affectedSectionIds={userScope} currentVision={...} onComplete={handleInterviewComplete} onBack={...} />
   - If step === "preview": <AmendmentPreview amendments={amendments} onContinue={handlePreviewContinue} onBack={...} />
   - If step === "cascade-review": <CascadeReviewPanel cascadePlan={cascadePlan} onConfirm={handleCascadeConfirm} onBack={...} />
   - If step === "confirming": <ConfirmationModal {...} onConfirm={handleApply} />
   - If step === "applying": <ApplyProgress {...} />
   - If step === "complete": <SuccessScreen />
   - If step === "waiting-approval": <ApprovingWaitingState />
   - If step === "error": <ApplyErrorDisplay error={applyError} onRetry={...} onClose={...} />

5. **Persistence:**
   - Auto-save step + state to worker-state after each transition
   - Resume flow on plugin reload (useRepositionRunState hook handles this)

**Styling:** Reuse Phase 2/3 design tokens (spacing xs–3xl, typography roles, colors, accent CTA style)

**Testing:** Component test verifies:
- State transitions (empty → intent → scope → interview → preview → cascade → confirming → applying)
- Handler calls (shift classification, amendment generation, cascade planning, apply orchestration)
- Error recovery (error state → retry)
- Resume from cache (load cached run → resume at scope-confirm)

| Boundary | Description | Risk |
|----------|-------------|------|
| Founder input → UI state | Intent, scope selections, interview answers, cascade decisions | Low — all inputs validated in RepositionPanel state machine; invalid states rejected early |
| UI state → backend orchestrators | Amendments, cascade plan, apply request | Low — UI state matches backend type contracts; type safety via TypeScript |
| Cascade decisions → apply | Per-agent keep/apply decisions | Low — decisions persisted in RepositionRunState; cannot apply override agents without founder checkbox confirmation (D-10) |
| Worker-state persistence → UI state | Cached run state across sessions | Medium — if worker-state corrupted, cached run may be partial; UI gracefully falls back to empty state on error |

| T-05-11 | Tampering | Cascade decisions | mitigate | Custom-override agents require explicit checkbox confirmation before "Apply" enabled; cannot bypass via UI manipulation (checkbox state gates button click) |
