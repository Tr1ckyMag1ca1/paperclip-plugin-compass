<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Mode Apply ↔ Memory Recording | Each mode applies changes independently; memory recording is advisory (failure doesn't revert Apply success) |
| Drift Detection ↔ Dedup Logic | Prior findings inform current drift report, but dedup is a filter only (never rejects founder input) |
| ASSESS-09 Context Refresh ↔ Repeat Noise Suppression | Plugin helps founder avoid noise, but founder can still see full drift report if needed (future: add "show suppressed" toggle) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-07 | Tampering | Apply success → memory recording async call | mitigate | Async call wrapped in try-catch; failure doesn't revert Apply (memory is secondary); audit logged |
| T-06-08 | Information Disclosure | Memory findings aggregate across modes; founder could see sensitive decisions | accept | Findings contain only summaries (not full content); sensitive data stays in VISION/issues; memory is for founder's reference only |
| T-06-09 | Denial of Service | ASSESS-09 dedup with millions of open findings (slow substring match) | accept | v1 doesn't optimize substring matching; expected workload is 10-50 findings per company; if > 100 open findings, dedup may be slow but doesn't block Assess |

</threat_model>
