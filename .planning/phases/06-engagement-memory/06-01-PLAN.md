<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Memory Store ↔ Documents Table | Plugin writes engagement history to documents table via SDK; unauthorized access to documents table is not the plugin's concern (Paperclip enforces RLS) |
| Routine Scheduling ↔ Paperclip Scheduler | Plugin writes cron expressions to routines table; Paperclip scheduler fires routines and invokes worker handlers; plugin trusts Paperclip's scheduler |
| Founder Intent ↔ Finding Status | Founder manually transitions finding status (addressed/invalidated); plugin does not auto-invalidate (except Assess dedup against open findings) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Tampering | Engagement history document in documents table | mitigate | All writes via SDK adapter (XC-01); no direct Postgres access; Paperclip RLS enforces company isolation |
| T-06-02 | Spoofing | Finding source/run_id attribution | mitigate | Finding.run_id comes from ApplyResult.runId (set by Apply orchestrator); each Apply run is founder-initiated and founder-confirmed |
| T-06-03 | Repudiation | Founder marks finding as addressed (but founder denies it) | accept | Low-priority finding-status operation; audit trail in status_history captures who/when; no compliance requirement for this operation |
| T-06-04 | Information Disclosure | Other company's findings visible in history tab | mitigate | Plugin loads findings for active company only; SDK SDK provides company context; Paperclip enforces company isolation at API level |
| T-06-05 | Denial of Service | Routine firing every minute (cron bomb) | mitigate | Cron validation in validateCronExpression; founder cannot enter invalid cron (form validation + server-side check); Paperclip scheduler rate-limits routine executions |
| T-06-06 | Elevation of Privilege | Routine runs with founder privileges but queues wakeups for CEO agent | mitigate | Routines fire in worker context (same privilege as any mode Apply); wakeups are queued with normal approval flow (per company approval routing config); no elevation |

</threat_model>
