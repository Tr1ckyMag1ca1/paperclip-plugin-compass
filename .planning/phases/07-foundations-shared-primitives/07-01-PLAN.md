<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Component props → Tailwind classes | Prop values (variant, padding) determine CSS classes rendered; malformed values could break layout |
| Icon prop → React rendering | Icon prop is optional React component; must accept className prop to avoid runtime errors |
| Children prop → DOM structure | Children are freely composed by caller; Card/SectionHeader don't validate or constrain structure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Tampering (CSS injection) | Card/SectionHeader className composition | mitigate | All Tailwind classes are static string literals (not template-string user input). No dynamic class construction from untrusted data. Tailwind JIT purge prevents unintended class injection. |
| T-07-02 | Information Disclosure (design token values) | Host CSS variable inheritance | accept | Token values (colors, spacing) are visual only; no sensitive data in design tokens. Host manages CSS variables; plugin inherits passively. |
| T-07-03 | Denial of Service (excessive children) | Card children prop | accept | No validation on children; caller bears responsibility. Card is a simple layout container; unbounded children are caller's concern, not a plugin security issue. |

**Phase 7 Security Posture:** No new attack surface. UI components are presentational; no data mutations, no API calls, no authentication logic. Inherits Plugin SDK + host security model.

</threat_model>
