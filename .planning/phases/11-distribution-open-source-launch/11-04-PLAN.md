  <action>
Create `.github/workflows/release.yml` with the following structure (per D-03, D-04):

```yaml
name: Release & Publish

on:
  push:
    tags:
      - 'v*.*.*'

permissions:
  contents: read
  id-token: write
  releases: write

jobs:
  verify-and-publish:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'pnpm'

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run full verify gate
        run: npm run verify
        # This runs: typecheck + lint:shim + test:run + size-limit + check-externals + npm pack dry-run

      - name: Build plugin bundles
        run: npm run build

      - name: Pack for npm
        run: npm pack

      - name: Publish to npm
        run: npm publish --access public
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}

      - name: Extract version and changelog notes
        id: release_info
        run: |
          VERSION=${GITHUB_REF#refs/tags/v}
          echo "version=$VERSION" >> $GITHUB_OUTPUT
          # Extract CHANGELOG section for this version (simplified; adjust regex as needed)
          NOTES=$(awk '/^## \['"$VERSION"'\]/,/^## \[/' CHANGELOG.md | head -n -1 | tail -n +2)
          echo "notes<<EOF" >> $GITHUB_OUTPUT
          echo "$NOTES" >> $GITHUB_OUTPUT
          echo "EOF" >> $GITHUB_OUTPUT

      - name: Create GitHub Release with .tgz artifact
        uses: softprops/action-gh-release@v1
        with:
          files: ./paperclip-plugin-compass-*.tgz
          body: ${{ steps.release_info.outputs.notes }}
          tag_name: ${{ github.ref_name }}
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

Key details:
- Trigger: `on.push.tags` with pattern `v*.*.*` (e.g., v1.1.0)
- Permissions: minimal — `contents: read` (checkout), `id-token: write` (OIDC trusted publishing for npm), `releases: write` (GitHub release creation)
- Jobs: single `verify-and-publish` job
- Steps:
  1. Checkout code
  2. Setup Node.js >=20 (required by esbuild + Plugin SDK)
  3. Install pnpm dependencies with frozen lockfile
  4. Run full `npm run verify` gate (all 6 checks: typecheck, lint:shim, test:run, size, externals, npm pack dry-run)
  5. Build plugin bundles (`npm run build`)
  6. Pack for npm (`npm pack` produces .tgz file)
  7. Publish to npm with `--access public` (per D-01) using `NPM_TOKEN` secret
  8. Extract version and CHANGELOG notes for GitHub release
  9. Create GitHub release with .tgz artifact and CHANGELOG-derived release notes

Note: `npm publish` without `--dry-run` actually publishes; `NODE_AUTH_TOKEN` env var is read by npm CLI for authentication. Ensure `NPM_TOKEN` secret is provisioned in repo Settings before tagging.

```yaml
      - name: Checkout code

        uses: actions/setup-node@v4

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Run verification gate

        # Runs: typecheck + lint:shim + test:run + size-limit + check-externals + npm pack dry-run

      - name: Build plugin bundles
        run: npm run build
```

Key details:
- Trigger: `on.pull_request` to main branch (protects main from broken commits)
- Permissions: minimal — `contents: read` (checkout), `checks: write` (report check status)
- Jobs: single `verify` job
- Steps:
  1. Checkout code
  2. Setup Node.js >=20
  3. Install pnpm dependencies
  4. Run full `npm run verify` gate (gating criteria for PR approval)
  5. Build plugin bundles (ensures build succeeds on PR changes)

This workflow runs on every PR and fails if any of the 6 verification checks fail (typecheck, lint:shim, test:run, size-limit, externals, npm pack). Combined with CODEOWNERS + GitHub branch protection, this enforces quality before merge.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions secrets | NPM_TOKEN stored in repo Secrets, accessed only by release workflow |
| npm registry publishing | npm CLI reads NODE_AUTH_TOKEN env var for authentication |
| GitHub release artifacts | .tgz file and release notes published to GitHub as public release |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-11 | Spoofing | Attacker pushes tag v1.1.0 and publishes malicious version | mitigate | GitHub branch protection on main + CODEOWNERS enforce PR review before code merges; tag push requires commit history clean (PR-approved only) |
| T-11-12 | Tampering | CI workflow modifies CHANGELOG or package.json during publish | mitigate | Workflow is read-only on repo (permissions: contents:read); only npm CLI writes to registry (via NPM_TOKEN) |
| T-11-13 | Disclosure | NPM_TOKEN leaked in workflow logs | mitigate | GitHub Actions masks secrets in logs automatically; NODE_AUTH_TOKEN used as env var (not echoed). npm CLI does not print token in logs. |
| T-11-14 | Denial | Failed verify gate blocks publish; old version stuck on npm | mitigate | Verify gate must pass before publish; if gate fails, tag remains in git but npm publish blocked (retry after fix). Rollback via `npm deprecate` if broken version ships (D-08) |
| T-11-15 | Information | Release notes contain sensitive commit messages | mitigate | Release notes derived from CHANGELOG.md only (author-written, reviewed); not from raw git log. CHANGELOG follows keepachangelog (user-friendly, sanitized) |
</threat_model>
