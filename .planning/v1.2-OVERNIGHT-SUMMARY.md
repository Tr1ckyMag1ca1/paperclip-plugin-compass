## Decisions logged

1. **Skipped formal v1.2 milestone ceremony.** The GSD workflow for new milestones requires interactive gates (questioning, summary confirmation, roadmap review). User was about to sleep, so I deviated to ship the onboarding work directly as v0.3.0 — minor bump for new feature surface. Rationale: shipping the visible UX overhaul matters more than the bookkeeping of a milestone.md file. v1.2 milestone can be retroactively documented if desired, or v1.1 can be reframed to include this work.

2. **WelcomeCard dismissal in localStorage, not worker state.** Adding worker-state persistence would require a new action handler + state schema entries. localStorage gives per-browser dismissal, which is acceptable for a transient onboarding hint. If the user dismisses it on laptop and then opens Compass on a different machine, the welcome shows again — that's fine for v1.

3. **HelpTip tests are structure-only.** The codebase convention (per `tests/ui/Card.spec.ts` comment) defers full render tests until jsdom is wired into vitest config. HelpTip uses hooks (`useState`, `useId`, `useRef`, `useEffect`) which can't be invoked outside a React renderer, so testing strategy stayed minimal: assert export shape and prop signature length only.

4. **v0.3.0 not 0.2.9.** Onboarding adds new feature surface (HelpTip primitive, WelcomeCard component) — minor bump per semver. v0.2.x patches were all bug fixes.

## Two upstream Paperclip host bugs surfaced (not fixed)

Worth filing in the host repo, not blocking Compass:

1. **CLI install reports stale version string** — `paperclipai plugin install <pkg>` echoes the previously-installed version rather than the just-installed one. Cosmetic but confusing; led to multiple "wait, did it actually upgrade?" cycles tonight.
2. **Plugin reinstall doesn't update the `plugins.version` DB column.** The on-disk `node_modules/<pkg>/package.json` and `dist/manifest.js` get the new version, but the DB row keeps the old value, and the plugin-loader reads version from the DB row. Forces a manual `UPDATE plugins SET version = '...' WHERE plugin_key = '...'` after every upgrade. This is what made every deploy tonight a 4-step dance instead of 1 step.

## Quick triage if anything is broken when you wake up

- **Plugin won't load** → `ssh paperclip-vps "docker logs docker-server-1 --tail 100 | grep compass"` — check for activation errors
- **Old version showing** → DB row out of sync with disk. Repeat: `npm install` in `/paperclip/.paperclip/plugins/`, `UPDATE plugins SET version` in psql, restart container
- **"failed to render" red box** → some other date-string-on-bridge bug. Pattern is `inventory.<dateField>.getTime()` without `new Date(...)` wrapper. Grep src/ for `.getTime()` to find candidates.
- **Want to roll back** → `npm install paperclip-plugin-compass@0.2.8` in plugins dir, set DB version to 0.2.8, restart.
