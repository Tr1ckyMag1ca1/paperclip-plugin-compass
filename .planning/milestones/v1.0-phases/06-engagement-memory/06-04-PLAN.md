<threat_model>
## Trust Boundaries

| Boundary | Description |
|-----------|-------------|
| Routine Scheduler ↔ Worker Handler | Paperclip fires routine.onFire with companyId + routineId; plugin invokes mode (Assess/Revive); results posted to memory |
| Memory Recording ↔ Dedup Prevention | Multiple routine fires with same finding should not duplicate (idempotency keys prevent); but also shouldn't suppress legitimate new findings |
| Worker State ↔ Plugin State | Worker-state caching (60s TTL) may be stale; UI refetch() invalidates cache on user action |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-13 | Tampering | Routine fires, handler updates routine.last_run_at | mitigate | All writes via SDK adapter (XC-01); audit logged; Paperclip enforces RLS on routines table |
| T-06-14 | Spoofing | Worker handler receives routineId from Paperclip scheduler; could be spoofed | accept | Paperclip scheduler is trusted; plugin only fires routines it created (for its company); cross-company attack blocked by RLS |
| T-06-15 | Denial of Service | Routine fires every second (if cron bomb created) | accept | Paperclip scheduler enforces rate limiting; plugin can't control firing frequency (only creation) |
| T-06-16 | Information Disclosure | routine.onFire handler logs findings to console | mitigate | Findings contain only summaries; full content stays in VISION/issues; console logs are plugin logs (founder can read) |

</threat_model>
