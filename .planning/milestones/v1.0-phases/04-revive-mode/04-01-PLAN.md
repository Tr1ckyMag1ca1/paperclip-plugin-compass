<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Revive classifier → Activity Data | Untrusted activity snapshot input (user-modified issues/comments) — classifier processes it but produces only diagnostic output, no writes |
| Adapter.closeIssue / addIssueComment / updateIssue | Founder-triggered writes to Paperclip; per XC-01, all route through SDK chokepoint |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Tampering | classifyStall heuristics | mitigate | Hard-coded thresholds (14 days, 30 days, etc.) documented inline; no user-configurable values in v1; bounds checking on confidence scores (0..1) |
| T-04-02 | Denial of Service | classifyStall recursion | mitigate | Pure functions, no unbounded loops; O(n) over activity items; activity snapshot pre-filtered to 30 days |
| T-04-03 | Information Disclosure | Activity snapshot reading | accept | Compass already has read access to all issues/comments per Phase 1 inventory; revive classifier reads same data |
| T-04-04 | Tampering | Adapter audit logging | mitigate | All writes (closeIssue, addIssueComment, updateIssue) logged with timestamp + source "compass:revive:{action}" for founder audit trail |
| T-04-05 | Elevation of Privilege | Adapter idempotency keys | mitigate | Idempotency keys prevent replay attacks; each action attempt has unique key; keys scope to company_id to prevent cross-company collision |
</threat_model>
