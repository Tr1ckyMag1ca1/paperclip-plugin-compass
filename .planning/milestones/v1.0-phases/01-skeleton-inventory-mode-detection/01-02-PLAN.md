Per MODE-01 and MODE-02, implement pure functions (no I/O) that classify company state deterministically.

**src/primitives/mode-detect.ts:**

Export type `Mode = "Found" | "Assess" | "Revive" | "Reposition"`

Export function `detectMode(inventory: InventorySnapshot): Mode`:
- **Hard rules (no LLM, deterministic, per MODE-01 and MODE-02):**
  1. If `!inventory.visionExists && inventory.agentCount === 0`: return `"Found"` (new company)
  2. Else if `inventory.visionExists && inventory.latestHeartbeat`:
     - Calculate `daysSinceHeartbeat = (Date.now() - inventory.latestHeartbeat.getTime()) / (1000 * 60 * 60 * 24)`
     - If `daysSinceHeartbeat < 7`: return `"Assess"` (healthy company with recent heartbeats)
  3. Else if `inventory.visionExists && (!inventory.latestHeartbeat || inventory.blockerCount > 2)`: return `"Revive"` (stalled company)
  4. Else: return `"Reposition"` (healthy company, founder-initiated shift; requires override in MODE-03)
- Rules are deterministic; no randomness, no LLM calls
- Returns exactly one of four modes

Export function `classifyChatInput(input: string): Mode | null` (per MODE-04):
- Accept user text input from chat
- Lightweight regex patterns only:
  - If input matches `/assess|audit|drift|review/i`: return `"Assess"`
  - If input matches `/revive|unstuck|blocked|stall/i`: return `"Revive"`
  - If input matches `/reposition|pivot|rebrand|shift/i`: return `"Reposition"`
  - If input matches `/found|new|company|bootstrap/i`: return `"Found"`
  - Else: return `null` (fallback to auto-detected mode)
- Case-insensitive matching
- No SQL, no command injection surface (founder-controlled input only)

**Rationale:**
- Hard rules are fast, deterministic, debuggable, zero token cost (vs LLM)
- Founder override (MODE-03) in Plan 3 handles edge cases where hard rules misclassify
- Chat classifier fallback to auto-detected mode ensures safe behavior if keywords don't match

This satisfies MODE-01, MODE-02, and MODE-04 (all hardcoded, testable, no external dependencies).

```typescript
import { definePlugin, runWorker, type PluginContext } from "@paperclipai/plugin-sdk";
import manifest from "./manifest";
import { loadInventory } from "./primitives/inventory";
import { detectMode } from "./primitives/mode-detect";

const plugin = definePlugin({
  async setup(ctx: PluginContext) {
    // D-08 schema validation (from Plan 1)
    try {
      await ctx.agents.list();
      await ctx.issues.list();
      await ctx.documents.list();
      ctx.logger.info("Compass schema validation passed");
    } catch (err) {
      throw new Error(`Schema validation failed: ${err.message}. See SCHEMA.md.`);
    }

    // NEW: Register data handlers (D-04, D-20, D-21)
    await registerDataHandlers(ctx);
  },

  async onHealth() {
    return { status: "ok", message: "Compass ready" };
  },
});

async function registerDataHandlers(ctx: PluginContext): Promise<void> {
  // Handler: getInventory (D-04, INV-01/INV-02/INV-03)
  // Per D-21: Inventory is queried once and passed to mode detection
  ctx.data.register("getInventory", async (params: { companyId: string }) => {
    const inventory = await loadInventory(ctx, params.companyId);
    return inventory;
  });

  // Handler: getDetectedMode (D-20, MODE-01/MODE-02)
  // Mode detection as pure function receiving inventory snapshot
  ctx.data.register("getDetectedMode", async (params: { companyId: string }) => {
    const inventory = await loadInventory(ctx, params.companyId);
    const mode = detectMode(inventory);
    return { mode, inventory };
  });

  // Handler: setModeOverride (D-09, MODE-03)
  // Store founder's manual override in Plugin SDK worker-state (host-persisted per-company)
  ctx.actions.register("setModeOverride", async (params: { companyId: string; mode: string }) => {
    await ctx.state.set(`modeOverride:${params.companyId}`, params.mode);
    return { success: true, mode: params.mode };
  });

  // Handler: getModeOverride (D-09)
  // Retrieve stored override or null if not set
  ctx.data.register("getModeOverride", async (params: { companyId: string }) => {
    const override = await ctx.state.get(`modeOverride:${params.companyId}`);
    return { override: override ?? null };
  });
}

export default plugin;
runWorker(plugin, import.meta.url);
```

**Why this pattern:** Plugin SDK's `ctx.data.register()` and `ctx.actions.register()` are the standard way to wire worker-side logic for UI consumption (per Kitchen Sink example and RESEARCH.md resolved question #3). The UI will call `usePluginData("getDetectedMode", { companyId })` to fetch both inventory and detected mode, and `usePluginAction("setModeOverride")` to persist overrides. This eliminates the "Alternatively..." pattern and commits to the single, proven SDK wiring.

This satisfies D-04, D-09, D-20, D-21, MODE-01, MODE-02, MODE-03, and INV-01/INV-02/INV-03 (all SDK data handlers wired for Plan 3 UI to consume).
