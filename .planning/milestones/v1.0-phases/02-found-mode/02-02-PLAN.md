### Key Decision Points

**D-09: Sequential Write + Rollback Strategy**
- NOT true transactions (Plugin SDK doesn't support)
- Instead: preflight → sequential writes in dependency order → compensating rollback on failure
- Rollback must be reverse order: wakeups (if any) → issues → agents → VISION doc
- If rollback step fails, halt and return explicit manual cleanup list to founder

**D-10: Idempotency Key Format**
- Format: `compass:found:${company_id}:${agent_id}:${apply_run_id}`
- `apply_run_id` is UUID generated at start of Apply
- Stable across retries: same company + agent + run ID = same key
- Checked before queueing: if key already exists in agent_wakeup_requests, skip insert

**D-11: Dual-Path Agent Instruction Routing**
- Per Paperclip schema, `agent.adapter_config.instructionsBundleMode` can be:
  - `null` or `"external"` → write to `agent.adapter_config.instructionsRootPath` or similar
  - `"managed"` → write to UUID-based managed path via Plugin SDK
- Plugin code in apply.ts calls adapter.writeAgentInstructions(agent, body)
- Adapter handles the branch logic, not apply.ts (PITFALLS.md Pitfall 2 prevention)

**Write Order Dependency**
1. VISION.md document (others reference it)
2. Agents (VISION created, agents created in parallel possible but implemented sequentially for simplicity)
3. Kickoff issues (each issue targets an agent; agents must exist)
4. Wakeups (queued last so failure doesn't leave hanging wakeups)

On failure at any step, rollback is reverse order.

   ```
     result.visionDocId = docId;
   ```

   ```
   catch (err) {
     const rollbackErrors: string[] = [];
     
     // Rollback in REVERSE order: wakeups (none to delete, they queue-only)
     // → issues → agents → VISION doc
     
     // Rollback issues
     if (result.issueIds) {
       for (const issueId of result.issueIds) {
         try {
           await adapter.deleteIssue(ctx, companyId, issueId);
         } catch (rollbackErr) {
           rollbackErrors.push(`Failed to delete issue ${issueId}: ${rollbackErr}`);
         }
       }
     }
     auditLog.push({ step: "rollback-issues", success: rollbackErrors.length === 0, timestamp: now });
     
     // Rollback agents
     if (result.agentIds) {
       for (const agentId of result.agentIds) {
         try {
           await adapter.deleteAgent(ctx, companyId, agentId);
         } catch (rollbackErr) {
           rollbackErrors.push(`Failed to delete agent ${agentId}: ${rollbackErr}`);
         }
       }
     }
     auditLog.push({ step: "rollback-agents", success: rollbackErrors.length === 0, timestamp: now });
     
     // Rollback VISION doc
     if (result.visionDocId) {
       try {
         await adapter.deleteDocument(ctx, companyId, result.visionDocId);
       } catch (rollbackErr) {
         rollbackErrors.push(`Failed to delete VISION doc ${result.visionDocId}: ${rollbackErr}`);
       }
     }
     auditLog.push({ step: "rollback-vision", success: rollbackErrors.length === 0, timestamp: now });
     
     result.success = false;
     result.rollbackApplied = rollbackErrors.length === 0;
     result.rollbackErrors = rollbackErrors;
     result.errors = [String(err), ...rollbackErrors];
     result.auditLog = auditLog;
     return result;
   }
   ```

## Dual-Path Routing Safety (PITFALLS Pitfall 2)

Per `adapter.writeAgentInstructions`:
- Checks `agent.adapter_config.instructionsBundleMode`
- Routes to managed UUID path if mode === "managed"
- Routes to external friendly path if mode === null or "external"
- Throws error if no valid path found
- All branching logic in adapter, not caller (apply.ts can't misroute)

## Idempotency Key Safety (PITFALLS Pitfall 1)

Per `adapter.queueWakeup`:
- Validates key format via regex before insert
- Checks if key already exists in agent_wakeup_requests before queuing
- If key exists with status "queued" or "pending", skips insert (idempotent)
