# Phase 5 — Reposition Mode UI Design Contract

> Visual and interaction contract for Reposition Mode shift description, scoped re-interview, preview, cascade review, and Apply flow. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Paperclip host design tokens only |
| Preset | not applicable |
| Component library | Plugin SDK UI components (MetricCard, StatusBadge, DataTable, LogView, ActionBar) |
| Icon library | Lucide React (^1.14.0) |
| Font | Inherited from Paperclip host (no custom font stack) |

**Notes:**
- Inherits Phase 2 + Phase 3 + Phase 4 design system entirely (same spacing scale, typography, color system, class naming)
- No additional third-party component registry — Plugin SDK UI only
- Reuses Phase 2/3/4 components: `InterviewSection.tsx`, `QuestionRenderer.tsx`, `SectionNavRail.tsx`, `ConfirmationModal.tsx`, `ApplyProgress.tsx`, `ApplyErrorDisplay.tsx`, `CustomOverrideWarning.tsx`, `AmendmentDiff.tsx`
- All styling via Paperclip host design token classes (e.g., `px-lg`, `text-body`, `text-heading`, `bg-card`, `border-border`, `text-accent`, `text-destructive`)

## Spacing Scale

**Inherited from Phase 2 (unchanged):**

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, scope checkbox spacing |
| sm | 8px | Compact form element spacing, list gaps, scope checkbox list gap |
| md | 16px | Default form field padding, section gaps, textarea padding |
| lg | 24px | Major section padding, modal padding, RepositionPanel header padding |
| xl | 32px | Layout column gaps, interview panel padding |
| 2xl | 48px | Major section breaks, panel boundaries |
| 3xl | 64px | Full-page top/bottom spacing (sidebar width constraint) |

**Exceptions (Phase 5 specific):**
- Intent textarea padding: `p-lg` (24px) with `min-h-24` height
- Scope confirmation checkbox list: `gap-sm` (8px vertical between items)
- Cascade per-agent decision card padding: `p-md` (16px)
- Sidebar width constraint: ~360px — no horizontal scrolling

## Typography

**Inherited from Phase 2 + Phase 3 + Phase 4 (unchanged):** Two font weights only — 400 (normal) and 700 (bold).

| Role | Size | Weight | Line Height | Class Usage | Phase 5 Application |
|------|------|--------|-------------|-------------|-------------------|
| Body (paragraph) | 14px | 400 (normal) | 1.5 (24px) | `text-body font-normal` | Intent textarea placeholder/description, scope confirmation helper text, cascade review explanations, per-agent override warnings |
| Label (form labels, captions) | 12px | 400 (normal) | 1.4 (17px) | `text-label font-normal` | Scope section headers, scope checkbox labels, cascade decision metadata, per-agent custom-override indicator |
| Heading (section headers, h3/h4) | 18px | 700 (bold) | 1.3 (23px) | `text-heading font-bold` | "Describe the shift" section header, "Scope confirmation" section header, cascade section titles, per-agent card title |

**No monospace fonts in v1** — diffs in cascade review render in proportional body font with semantic styling via `AmendmentDiff` component.

## Interaction Patterns

### RepositionPanel Layout (Main Entry Point)

**Header** (fixed at top, sticky):
1. **Company Name** — left-aligned, `text-display font-bold`
2. **Subheading** — below company name, `text-body font-normal` light gray: "Describe the strategic shift and we'll guide you through updating your company."
3. **Action Buttons** (right-aligned):
   - "Discard shift" text button (secondary, gray) — only appears if reposition in progress

**Main content area** (scrollable):
- **If no reposition in progress:** Empty state showing "Run a drift audit or make a strategic shift"
- **If reposition in progress:** Multi-phase flow below

---

### Phase 1: Intent Textarea ("Describe the shift")

**Header:** "Describe the shift" in `text-heading font-bold`

**Textarea element:**
- Placeholder text with examples per D-15: "Describe the shift in plain English. Examples: 'rebrand toward compliance', 'narrow focus to enterprise customers', 'tighten our voice'."
- Padding: `p-lg` (24px), min-height `min-h-24`
- Hint text below: "Be specific about the direction change, not just internal improvements." in `text-foreground/70`
- Auto-persists to Plugin SDK worker-state on blur per Phase 2 pattern

**Buttons:**
- "Continue" (primary, accent style) — disabled until founder types ≥20 characters
- On click: shift classifier runs (pure function, no LLM) → surfaces classified sections → advances to Phase 2

---

### Phase 2: Scope Confirmation ("Which sections change?")

**Header:** "Which sections change?" in `text-heading font-bold`

**Helper text:** "These sections will be re-interviewed. Add or remove any." in `text-foreground/70`

**Checkbox list:**
- Classified sections displayed as checkboxes (checked by default, per D-02 threshold 0.4)
- Each item: checkbox + section name + optional "(optional)" label per D-02 (founder can deselect)
- Spacing: `gap-sm` (8px) between items
- Sections shown in VISION template order (mission, mandate, voice, principles, success_criteria, growth_strategy)
- Example:
  ```
  ☑ Mission
  ☑ Voice
  ☑ Product direction
  ☐ Revenue model (optional)
  ```

**Buttons:**
- "← Back to shift description" (secondary text button)
- "Continue to interview" (primary, accent style) — enabled only if ≥1 section selected

---

### Phase 3: Scoped Re-Interview (Reused from Phase 2)

**Structure:**
- Reuses Phase 2 `InterviewSection.tsx`, `QuestionRenderer.tsx`, `SectionNavRail.tsx` verbatim
- Section nav rail shows ONLY affected sections (filtered via `src/reposition/scope-filter.ts` per D-05)
- Questions pre-filled with current VISION answers where possible (via `getSectionAnswerSeed` per D-06)
- Founder edits answers, validates required fields per Phase 2 quality-check pattern

**Section progression:**
1. All affected sections in VISION order
2. Each section's questions as in Phase 2
3. "← Back" button navigates to prior section or back to scope confirmation if first section
4. On final section: "Review and preview" button instead of "Next: [section]"

**Buttons:**
- "← Back to scope confirmation" (secondary text button) — returns to Phase 2, preserves all answers
- "Review and preview" (primary, accent style) — final section only, validates required fields, advances to Phase 4

---

### Phase 4: Preview Screen (Amendment Display)

**Header:** "Review the proposed changes" in `text-display font-bold`

**Content (scrollable):**
1. **Per-section amendment preview:**
   - Section name heading: `text-heading font-bold`
   - Amendment diff in collapsible `<details>` (reuses Phase 3 `AmendmentDiff` verbatim)
   - Format: unified diff (from Phase 3 UI-SPEC.md) showing before → after
   - Example:
     ```
     - voice: "technical and formal"
     + voice: "approachable, expert, friendly"
     ```
   - Expanded by default (founder reviews all before cascade)

**Buttons:**
- "← Back to interview" (secondary text button) — returns to interview, preserves answers + edits
- "Review cascade" (primary, accent style) — advances to Phase 5 cascade review

---

### Phase 5: Cascade Review ("Which agents get updated?")

**Header:** "Which agents get updated?" in `text-heading font-bold`

**Helper text:** "These agents will receive new instructions from the repositioning. Skip any with custom overrides if you want to keep them." in `text-foreground/70` per D-10

**Per-agent decision cards:**

1. **Card header** (padded `p-md`, light `bg-card` background):
   - Left: Agent name + role in `text-body font-bold`
   - Right: Status indicator (affected section name in `text-label` gray)

2. **Card body** (padded `p-md`, white/background):
   - **Decision buttons** (flex row, two buttons):
     - "Keep custom" (left, gray text style by default) — if agent has custom overrides, this is the default (per D-10)
     - "Apply repositioning" (right, primary accent style when selected) — applies the amended section to this agent
   - **Custom override warning** (if agent has custom config):
     - Shows CustomOverrideWarning card (reuse Phase 3 component)
     - Checkbox: "I've reviewed the override conflict and approve cascading anyway"
     - Only allows "Apply repositioning" after checkbox confirmed

3. **Agent list grouping:**
   - All affected agents listed
   - Agents grouped by pod/role (optional, planner decides density)
   - Only agents whose config maps to amended sections shown (others filtered per D-09)

**Buttons:**
- "← Back to preview" (secondary text button) — returns to preview amendments
- "Apply repositioning" or "Apply with custom agent handling" (primary, accent style):
  - Enabled when all agents with custom overrides have explicit decision (keep/apply/merge)
  - Disabled state: "Select actions for all agents to continue" in gray
  - On click: opens final confirmation modal

---

### Final Confirmation Modal (Two-Stage Gate, Reused from Phase 2/3)

**Modal header:** "Apply repositioning?"

**Modal body:**
```
Apply will:
- Update [N] VISION.md section(s)
- Create [N] cascading issue(s) for affected agents
- Queue [N] wakeup request(s)

Amendment history preserved in VISION changelog.

Write count: [N] document(s) updated, [N] cascading issues, [N] wakeups
```

**Buttons:**
- "Cancel" (secondary) — returns to cascade review
- "I confirm — apply repositioning" (primary, accent) → runs Apply orchestrator

---

### Apply Progress UI (from Phase 2, Reposition variant)

**Modal or full-panel overlay (blocking interaction):**

Sequential step indicator:
```
Validating setup…
✓ Preflight checks
Amending vision document…
✓ VISION.md sections updated
Creating cascading issues…
✓ N affected agent issues created
Queuing wakeups…
✓ Wakeup requests queued
```

Each step shows:
- Status: "…" (in-progress) or "✓" (complete)
- Step name

**On success:**
```
✓ Company repositioned!

Your VISION document has been updated and [N] agents have been notified.
Check your company's issue list for cascading work items.

[Go to company] button → closes plugin, navigates to company
```

**On failure at any step:**
```
Apply failed: [Step name]

Error: [Readable error message]
Next step: [Recovery instruction]

Rollback:
✓ Cascading issues deleted
✓ VISION document reverted

[Retry] | [Close]
```

## Responsive Constraints

**Layout approach:**
- Main panel scrollable vertical (no horizontal scrolling)
- Textarea, scope checkboxes, preview diffs: full-width within `p-lg` padding

## Accessibility

- All interactive elements keyboard-navigable (Tab, Enter, Space)
- Textarea and checkboxes linked via `id` / `htmlFor`
- Decision buttons have clear `aria-label` for screen readers (e.g., "Keep custom for Agent Alice")

- Modal backdrop blocks background interaction (focus trap)
- Collapsible diffs have `aria-expanded="true|false"`

## Designer Notes (Claude's Discretion)

This contract locks the **what** (behavior + copy + visual relationships) but leaves **where** for the planner:

1. **Section nav rail placement in re-interview** — top tabs vs left sidebar rail? Recommend left-rail for consistency with Phase 2, but step indicator acceptable if space tight.
2. **Scope checkbox style** — checkboxes vs tag selector vs button toggles? Recommend checkboxes (familiar pattern, matches Phase 2), but planner may prefer compact tag toggles.
3. **Cascade decision UI layout** — per-agent cards (current spec) vs single scroll list vs two-column decision matrix? Recommend cards (clear agent identity + decision per card), but planner may stack vertically if sidebar tight.
4. **Preview amendment grouping** — all sections expanded by default (current) vs collapsed? Recommend expanded (founder reviews all at once), but planner may collapse low-priority sections to reduce cognitive load.
5. **Intent textarea size** — `min-h-24` (current) vs `min-h-32` or auto-expand on input? Recommend `min-h-24` with auto-expand on keystroke to match Phase 2 textarea patterns.

All above locked in **planner** phase per Phase 1 UI-SPEC.md conventions. UI-SPEC provides the contract; planner places components.
