## Overview

Compass v1.0 ships as a Paperclip plugin (TypeScript + React, peer-dep, Plugin SDK only). One in-app surface gives founders strategic + operational guidance across the full company lifecycle:

- **Found Mode** — vision-quest interview (6 sections, 29 questions) → VISION.md generation → two-stage approval gate → agent provisioning + kickoff issues + idempotency-keyed wakeups
- **Assess Mode** — deterministic drift detection vs 30-day activity window → grouped drift report with confidence scores → Amendment Protocol (default-NO + dated changelog) → cascade with custom-override warnings → per-company approval routing (`founder` | `founder+ceo`)
- **Revive Mode** — 5-cause stall classifier (single-blocker / strategic-drift / broken-integration / governance-loop / dead-agent) → founder-action queue document → 7 typed action handlers including one-click sample-pivot → incremental (non-batch) apply
- **Reposition Mode** — shift-classifier maps founder intent to affected VISION sections → scoped re-interview (subset of Found mode) → per-section amendment preview → cascade with per-agent keep/apply toggle
- **Engagement Memory** — `compass-engagement-history` document persists findings + routines across sessions → History tab in plugin UI with status/mode/date filters → scheduled check-ins via Paperclip routines (quarterly drift, monthly trust-gate, custom cron) → ASSESS-09 dedup suppresses repeat noise

All Paperclip access routes through a single SDK adapter chokepoint (XC-01); no direct Postgres, no raw HTTP, no FS writes for managed agents (XC-04, XC-05); all wakeups idempotency-keyed (XC-03); transactional Apply with compensating rollback (XC-02).

## Milestone Summary

**Key Decisions:**
- Plugin SDK only — no direct Postgres, no raw HTTP, no FS writes for managed agents (Plugin contract + portability)
- Hard-rules deterministic classifiers across mode-detection, drift detection, stall classification, shift classification (predictable, free, debuggable, no LLM tax)
- 30-day drift window fixed in v1 (signal-to-noise tradeoff; not user-configurable)
- Vision-quest 6-section full-depth interview (no condensed mode in v1)
- Engagement memory in `documents` table — no Paperclip core schema migration
- Per-company approval routing (`founder` default | `founder+ceo`) — flexibility without complexity
- Two-stage approval gate (preview + final modal) for any VISION write — XC-06 spirit
- Incremental Apply for Revive (per-action) vs batch transactional for Found/Assess/Reposition — different philosophies; document divergence
- All wakeups idempotency-keyed in format `compass:{mode}:{company}:{...}` — prevents duplicates on retry (XC-03)
- React peer-dep (not bundled) — host loads React 19 globally
- Esbuild markdown text-loader — interview content + VISION template ship as markdown for Aron-portability (XC-07)
- Co-maintainership baked in — README credits Aron Prins, CODEOWNERS routes PRs, DECISIONS.md + CONTRIBUTING.md + SCHEMA.md present

**Issues Resolved Mid-Build:**
- ASSESS-09 (context-refresh dedup) reassigned from Phase 3 to Phase 6 — depends on engagement memory infra
- esbuild markdown loader missing — added rawMarkdownPlugin to esbuild.config.mjs
- node:crypto bundled into UI — replaced with `globalThis.crypto.randomUUID()` (Web Crypto API works in Node ≥19 + browser)
- UI ↔ worker handler name mismatches in Phases 4 / 5 / 6 — closed via gap closure runs; smoke tests added in each integration spec to prevent regression
- Apply orchestrators couldn't call `recordFindingsToHistory` from browser context — moved the call to the worker handler layer (post-Apply recording)
- ASSESS-09 dedup hook wired in `runDriftAudit` worker handler (loads engagement history → passes priorOpenFindings to detectDrift)

**Issues Deferred (v1.1+):**
- LLM-aided variants of drift / shift / stall classifiers (hard-rules first per project constraint)
- Cross-company history rollup
- Memory export (JSON/CSV)
- Side-by-side amendment diff (v1 ships unified diff for sidebar fit)
- Live polling on founder+ceo approvals (v1 manual refresh)
- Per-pod cascade preview rolled up across many agents
- User-configurable drift window
- Cron-readable internationalization
- Custom-merge action for overridden agents in Reposition

**Technical Debt:**
- Plugin SDK v1.0.0 doesn't expose agent create/delete or first-class routines API — Phase 2 uses issue-based agent placeholders, Phase 6 stores routines in `EngagementHistory.routines[]`. Migrate to native APIs when SDK exposes them.
- Paperclip scheduler integration with `routine.onFire` handler relies on the scheduler invoking a matching handler name — verify in a live integration session before depending on auto-fire in production.
- esbuild bundles dist/* committed to repo for now; CI publishing pipeline can drop these once npm publish is wired.
